# Бот GAD-7 и PHQ-9 для Telegram

Бот проводит два коротких опросника, хранит результаты и каждую среду напоминает пройти их снова.

- **GAD-7**: 7 вопросов о тревоге, 0 до 21 балла.
- **PHQ-9**: 9 вопросов о настроении плюс десятый вопрос о том, насколько симптомы мешали жить. Десятый вопрос задаётся, но не входит в сумму баллов, как и предусмотрено самим опросником.
- Результаты живут в памяти процесса и параллельно пишутся в один JSON-снимок, поэтому история переживает перезапуск.
- Напоминание по средам с индивидуальным временем и часовым поясом у каждого пользователя.

Без зависимостей: только стандартная библиотека Node.js 16 и новее. Long polling, поэтому не нужны публичный домен, сертификат и веб-сервер.

## Быстрый старт

1. Получите токен у [@BotFather](https://t.me/BotFather): команда `/newbot`.
2. Задайте токен:

```text
cp telegram-bot/.env.example telegram-bot/.env
# впишите BOT_TOKEN в telegram-bot/.env
```

Либо через переменную окружения:

```text
export BOT_TOKEN=123456789:ваш-токен
```

3. Запустите бота:

```text
node telegram-bot/bot.mjs
```

В логе появится имя бота, путь к снимку данных и время следующего напоминания. Напишите боту `/start` в личном чате.

Посмотреть весь диалог локально, без токена и без сети:

```text
node telegram-bot/bot.mjs --demo
```

## Команды

| Команда | Что делает |
| --- | --- |
| `/start` | приветствие, дисклеймер и кнопки запуска |
| `/gad7` | пройти GAD-7 |
| `/phq9` | пройти PHQ-9 |
| `/results` | история результатов по обоим опросникам |
| `/last` | последний результат каждого опросника |
| `/remind` | показать настройки напоминаний |
| `/remind off`, `/remind on` | выключить или включить напоминания |
| `/remind 09:30` | своё время напоминания по средам |
| `/tz +3`, `/tz -05:30` | часовой пояс для времени и дат |
| `/export` | выгрузить свои данные в JSON |
| `/delete` | удалить все свои данные, с подтверждением |
| `/cancel` | прервать незаконченный опросник |
| `/about` | об опросниках, о порогах и о том, что хранит бот |
| `/help` | список команд |

Отвечать можно кнопками или цифрой от 0 до 3 в сообщении. Опросник идёт по одному вопросу, прошлый вопрос переписывается вместе с выбранным ответом, поэтому повторное нажатие старой кнопки ничего не меняет.

## Как считаются баллы

| Баллы GAD-7 | Оценка |
| --- | --- |
| 0 до 4 | минимальная тревога |
| 5 до 9 | легкая тревога |
| 10 до 14 | умеренная тревога |
| 15 до 21 | выраженная тревога |

| Баллы PHQ-9 | Оценка |
| --- | --- |
| 0 до 4 | минимальная выраженность |
| 5 до 9 | легкая |
| 10 до 14 | умеренная |
| 15 до 19 | умеренно тяжелая |
| 20 до 27 | тяжелая |

Порог 10 в любом из опросников бот отмечает как повод обсудить состояние со специалистом. Если в девятом вопросе PHQ-9 выбран любой вариант выше нуля, бот показывает блок поддержки с контактами из `CRISIS_CONTACT`, независимо от суммы баллов.

Бот не ставит диагноз. Это инструмент самонаблюдения и отслеживания динамики.

## Хранение данных

| Что | Где |
| --- | --- |
| пользователи, ответы, баллы, настройки, offset обновлений | `Map` в памяти процесса |
| тот же набор данных на диске | `telegram-bot/.data/results.json` |

Запись отложенная и атомарная: временный файл, `fsync`, затем `rename`. Прерванная запись не может испортить прошлый снимок. При остановке по `SIGINT` или `SIGTERM` бот сбрасывает данные на диск и выходит с кодом 0.

`MEMORY_ONLY=1` полностью отключает диск: бот работает только в памяти, история теряется при перезапуске.

### Сколько выдерживает такое хранение

Снимок сериализуется и пишется целиком, поэтому его стоимость растёт линейно. Замеры на одном ядре, по 20 прохождений на пользователя:

| Пользователей | Прохождений | Снимок | Одна запись |
| --- | --- | --- | --- |
| 1 000 | 20 000 | 4.3 МБ | 65 мс |
| 5 000 | 100 000 | 21.5 МБ | 745 мс |
| 10 000 | 200 000 | 42.9 МБ | 1345 мс |
| 5 000 (по 200) | 1 000 000 | 208.6 МБ | 6371 мс |

Запись синхронная, то есть на это время бот не обрабатывает сообщения. До нескольких тысяч активных пользователей это незаметно. На 24 МБ бот один раз пишет в лог предупреждение, что пора переходить на базу данных. Жёсткий предел 256 МБ: снимок такого размера бот откажется записать с внятной ошибкой, а не создаст файл, который потом не сможет прочитать. Для десятков тысяч пользователей замените `src/store.mjs` на SQLite, остальной код этого не заметит.

Роутер при этом не является узким местом: 253 000 апдейтов в секунду на одном ядре, около 0.03 мс процессорного времени на полное прохождение опросника. Реальный потолок скорости это лимиты Telegram, примерно 30 сообщений в секунду на бота и одно сообщение в секунду в один чат.

Хранится идентификатор чата, ответы и баллы каждого прохождения, настройки напоминаний. Имя, телефон и текст сообщений не сохраняются. `/export` отдаёт данные пользователю, `/delete` удаляет их целиком. В групповых чатах опросники не запускаются: ответы о самочувствии не должны попадать в общий чат.

Файл снимка содержит чувствительные данные о здоровье. Держите его на диске с ограниченным доступом (бот создаёт файл с правами `0600`) и не добавляйте в git: `telegram-bot/.data/` и `telegram-bot/.env` уже в `.gitignore`.

## Напоминания по средам

Каждые `TICK_SECONDS` секунд бот считает для каждого пользователя последний прошедший слот "среда, время напоминания" в его часовом поясе. Если слот новее отметки последней отправки, уходит напоминание с прошлыми баллами и кнопками запуска.

- Двойная отправка невозможна: отметка `lastRemindedAt` равна времени слота, а не времени отправки.
- Пропущенный слот старше `REMINDER_GRACE_HOURS` не досылается: если бот лежал сутки, пользователь не получит вчерашнее напоминание.
- Сбой сети оставляет слот незакрытым, и следующий тик попробует снова.
- Ответ `403` от Telegram означает, что бота заблокировали: напоминания для этого чата выключаются, чтобы не долбиться в закрытую дверь.
- Смещения фиксированные, без базы часовых поясов. При переходе на летнее время локальное время отправки сдвигается на час, пока пользователь не поправит `/tz`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | нет, обязательна | токен от @BotFather |
| `DATA_FILE` | `telegram-bot/.data/results.json` | путь к снимку |
| `MEMORY_ONLY` | `0` | `1` отключает запись на диск |
| `REMINDER_TIME` | `10:00` | время напоминания по умолчанию |
| `REMINDER_UTC_OFFSET` | `+3` | часовой пояс по умолчанию |
| `REMINDER_GRACE_HOURS` | `12` | окно досылки пропущенного слота |
| `CRISIS_CONTACT` | номера для России и findahelpline.com | контакты в блоке поддержки |
| `POLL_TIMEOUT_SECONDS` | `50` | таймаут long polling |
| `TICK_SECONDS` | `60` | период проверки напоминаний |
| `SESSION_IDLE_MINUTES` | `60` | через сколько забывается незаконченный опросник |
| `API_BASE` | `https://api.telegram.org` | адрес Bot API |

Токен не попадает ни в логи, ни в текст ошибок: клиент вырезает его из любой строки перед выводом.

## Автозапуск через systemd

```ini
[Unit]
Description=GAD-7 and PHQ-9 Telegram bot
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/unlazy
ExecStart=/usr/bin/node /opt/unlazy/telegram-bot/bot.mjs
Environment=BOT_TOKEN=123456789:ваш-токен
Environment=DATA_FILE=/var/lib/gad7-phq9-bot/results.json
Restart=always
RestartSec=5
NoNewPrivileges=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

Один токен обслуживается одним процессом: Telegram отдаёт `409 Conflict`, если `getUpdates` вызывают из двух мест одновременно.

## Тесты

```text
node telegram-bot/tests/run-tests.mjs
npm run test:bot
```

61 проверка без зависимостей и без обращений в сеть: подсчёт баллов и границы оценок, машина состояний опросника, снимок данных и его восстановление после битого файла, арифметика среды в разных часовых поясах, все ветки диалога, клиент Bot API на локальном сервере и цикл напоминаний.

## Структура

| Файл | Ответственность |
| --- | --- |
| `bot.mjs` | точка входа, long polling, тик напоминаний, корректная остановка |
| `src/instruments.mjs` | вопросы, варианты ответов, подсчёт баллов, оценки, флаг риска |
| `src/router.mjs` | обработка апдейтов, возвращает список вызовов Bot API и ничего не отправляет сам |
| `src/session.mjs` | состояние незаконченного опросника |
| `src/store.mjs` | данные в памяти плюс атомарный снимок |
| `src/reminders.mjs` | расчёт слота среды и отбор адресатов |
| `src/texts.mjs` | все русские тексты и форматирование сообщений |
| `src/telegram.mjs` | клиент Bot API на `node:https`, повторы, вырезание токена |
| `src/config.mjs` | чтение `.env` и переменных окружения, проверка значений |

Роутер синхронный и не делает ввода-вывода, поэтому любую ветку диалога можно проверить тестом без сети и без живого бота.

## Об опросниках

- GAD-7: Spitzer RL, Kroenke K, Williams JBW, Löwe B. A brief measure for assessing generalized anxiety disorder: the GAD-7. Arch Intern Med. 2006;166(10):1092-1097.
- PHQ-9: Kroenke K, Spitzer RL, Williams JBW. The PHQ-9: validity of a brief depression severity measure. J Gen Intern Med. 2001;16(9):606-613.
- Оригинальные бланки и инструкции по подсчёту: [phqscreeners.com](https://www.phqscreeners.com). Опросники семейства PHQ и GAD распространяются с пометкой, что для воспроизведения, перевода и распространения разрешение не требуется.

Русские формулировки вопросов в `src/instruments.mjs` это рабочий перевод, а не сертифицированная валидированная версия. Для клинического или исследовательского использования возьмите официальный перевод и сверьте текст построчно.

## Ограничения

- Опросники не ставят диагноз и не заменяют консультацию врача или психотерапевта.
- Бот не шифрует снимок данных: защита данных это права на файл и доступ к серверу.
- Один процесс на один токен, горизонтального масштабирования нет.
- Смещение часового пояса фиксированное, переходы на летнее время не отслеживаются.
